## 1. 깨뜨려보기 (10분)

`SyntaxDemoTest` 에서 `isEqualTo(2)` 를 `isEqualTo(3)` 으로 바꾸고 다시 돌린다.
실패 메시지를 읽는다. **기대값과 실제값을 어떻게 보여주는지** 눈에 익혀둔다.
확인했으면 되돌린다.

## 2. 직접 쓰기 (2시간)

`src/test/java/practice/FixedLengthMessageTest.java` 를 새로 만들고
아래 항목을 하나씩 테스트로 옮긴다. 구현 코드는 건드리지 않는다.

### 정상 동작
- [v] 문자 필드를 offset 과 length 로 꺼내면 값이 나온다
- [v] 문자 필드의 우측 공백이 제거된다
- [v] 숫자 필드의 좌측 0 패딩이 제거되고 숫자로 나온다
- [v] 전문 전체 길이를 반환한다

### 경계값
- [v] offset 0 에서 시작하는 필드
- [v] 전문의 마지막 바이트까지 정확히 채우는 필드
- [v] length 가 1 인 필드
- [v] 숫자 필드가 공백뿐이면 0 이 된다

### 예외
- [v] 생성자에 null 을 넣으면 실패한다
- [v] offset 이 음수면 실패한다
- [v] length 가 0 이하면 실패한다
- [v] offset + length 가 전문 길이를 넘으면 실패한다
- [v] 숫자 필드에 숫자가 아닌 값이 들어 있으면 실패한다

**예외 테스트는 메시지까지 확인한다.** 어떤 예외가 났는지만 보면
엉뚱한 이유로 난 예외도 통과해버린다.

## 3. 스스로 점검

다 쓴 뒤에 이렇게 확인한다.

- 테스트 이름만 읽어도 무엇을 보장하는지 알 수 있는가
- 한 테스트가 한 가지만 검증하는가
- `given` `when` `then` 이 구분되는가
- 구현을 한 줄 지웠을 때 **어떤 테스트가 깨질지 예상**되는가

마지막 항목이 핵심이다. 예상이 안 되면 그 코드는 테스트로 보호되지 않은 것이다.

## 4. 실제로 깨뜨려서 확인

`FixedLengthMessage` 에서 아래를 하나씩 지우고 테스트를 돌린다.
빨간불이 뜨지 않으면 그 부분은 아직 테스트가 없는 것이다.

- `stripTrailing()` 을 뺀다
- `offset + length > raw.length()` 검사를 뺀다
- `value.isEmpty()` 분기를 뺀다

전부 확인하면 되돌린다.

## 학습하면서 내가 배운점

### 단위 테스트 실행 방식
1. ./gradlew test 명령어를 통해 테스트를 실행할 수 있다. 대상은 옵션 설정을 따로 하지 않으면 src/test/java 아래의 활성화된 모든 테스트를 실행한다.
2. 성공한 테스트는 캐시되어 재실행되지 않는다. --rerun-tasks 옵션을 사용하여 다시 실행할 수 있다. 그래서 재실행하면 아무 결과가 나오지 않는다.
3. 실패한 테스트는 캐시되지 않으며, 실패한 테스트만 다시 실행된다. --tests 옵션을 사용하여 특정 테스트만 실행할 수 있다.
